# 实机测试记录：58 GB NTFS U 盘（Windows 10/11）

日期：2026-11-09
环境：Windows，U 盘通过 `\\.\G:` 只读访问（可移动盘无需管理员），盘为 **NTFS**、容量约 58 GiB。
测试前已把盘上原有文件备份到本地；恢复输出全部写到电脑本地磁盘，未写回 U 盘。

## 整盘容量测试结论（重要）

- 该 U 盘在 **≤4 GB 的写入/读回**下表现正常；但**写满整盘（约 62 GB）后读回校验失败**，说明它在
  大容量/持续写入场景下不可靠（疑似扩容盘或闪存/主控在高负载下出错）。
- 与最初的事故（复制小文件后内容变成旧数据残留）一致：**不建议再用这块盘保存重要数据**。
- 建议：
  1. 重要文件不要放这块盘；如刚买不久可考虑退换；
  2. 若还要用，写入后用 `filetool.py capacity` 复测，并对拷入文件做哈希校验；
  3. 不建议用它做备份盘/系统安装盘；
  4. 需要大容量时优先选择可全盘校验通过的正规存储。

## 本次测试带出的代码改进（已合入 v0.3.1）

1. **删除文件真实文件名恢复**：NTFS 删除后目录项里仍保留 `name + meta_addr`，TSK 的 `entry.info.meta` 可能为
   `None`；用 `meta_addr` 回查 MFT 记录（必须是“未分配”记录，避免目录项复用时误报），再与 MFT 未分配记录
   按 inode 去重 → 恢复时直接使用原文件名。
2. **恢复保留目录结构**：普通/删除文件按原相对路径恢复；孤儿 MFT 记录统一放 `_orphan/` 下。
3. 已补进 `tests/test_ntfs.py`（真实 NTFS 镜像 + 模拟删除记录断言），全部测试 9/9 通过。

## 说明

- 恢复测试的 SHA-256 校验在删除后、任何大量写入之前完成，结果有效；整盘容量测试之后的恢复结果会受
  “被删文件簇被复用”影响。
- 测试期间在 U 盘上创建的样本/测试文件已清理，原有文件保持不变。
